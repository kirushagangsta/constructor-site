# TemplateVue.js

## Зависимости

Обязательные зависимости прописаны в package.json

- Используем vue3 + nuxt3, если нужно выключить SSR, пишем ssr: false в конфиге
- В качестве ui-фреймворка испольуем tailwind
- В качестве стора pinia
- Для тривиальных задач lodash

Установка: `npm install`

- vue@3
- nuxt@3
- Используем Composition API для Vue
- @nuxtjs/tailwindcss@latest
- sass@latest --save-dev
- tailwind@latest --save-dev

## Архитектура директорий 

```bash

├── assets
│   ├── scss - директория с файлами стилей
│   │   └── main.scss - основной файл scss, куда импортируются все остальные
│   │   └── common - директория с файлами scss, разбитыми по категориям
│   │       └── **.scss 
│   ├── images - директория с .webp .png картинками
│   ├── svg - директория с .svg картинками
│   │   └── icons - директория с .svg иконками, используемыми в тегах i
│   └── fonts - директория с файлами шрифтов
├── components - директория с vue компонентами
│   └── Ui - директория с компонентами Ui-кита(кнопки, инпуты и прочее)   
├── composables - директория с переиспользуемыми функциями(composables) 
├── layouts - директория с переиспользуемыми паттернами страниц
├── middleware - директория с middleware-функциями для редиректа пользователей 
├── pages - директория с компонентами страниц 
├── plugins - директория с плагинами
├── public - директория со статическими файлами
├── store - директория с модулями стора(pinia)
└── utils - директория со вспомогательными функциями(форматтеры, хелперы и прочее)
```

## Тесты

Vitest + Vue Test Utils, окружение happy-dom. Nuxt для тестов не поднимается:
берётся только Vite с плагином Vue, а то, что Nuxt обычно авто-импортирует
(`ref`, `watch`, `useTemplateRef` и прочее), подставляется в `tests/setup.ts`.

```bash
npm test          # прогнать один раз
npm run test:watch
```

```
tests
├── setup.ts                  - подстановка авто-импортов Nuxt
├── utils
│   ├── node.spec.ts          - id блоков, копирование поддерева, путь и номер, текст
│   ├── move.spec.ts          - перенос блоков по дереву и запреты на невозможные переносы
│   └── history.spec.ts       - как журнал называет действие, сравнивая два состояния страницы
└── components
    └── Button.spec.ts        - Ui/Button: слот, иконка, варианты оформления, события
```

Что проверяется в первую очередь — места, где ошибка тихая и дорогая:

- **id блока не меняется при переносе.** На id завязаны стили (`n-<id>` в css)
  и записи журнала, поэтому тест следит, что после `moveNode` блок остаётся собой.
- **Номер позиции при переносе вниз.** Вырезанный блок сдвигает точку вставки,
  и без поправки блок встаёт не туда. Отдельным тестом закреплено и то,
  что перенос на соседнее место вниз считается бессмысленным.
- **Запреты.** Блок нельзя положить внутрь себя, внутрь своего потомка
  и внутрь пустого тега вроде `img`.
- **Текст не участвует в нумерации.** В `children` блоки и текст лежат вперемешку,
  а человеку показываются номера только по блокам.
- **Журнал понимает, что случилось, из самого дерева** — добавление, удаление,
  правку текста, стилей, атрибутов, смену тега и перенос.
